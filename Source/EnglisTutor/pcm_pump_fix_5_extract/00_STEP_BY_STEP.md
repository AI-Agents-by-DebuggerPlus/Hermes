# Hermes.EnglishTutorClient — Fix Pass #5: SCO hold ломает capture (0x88890008) + Play diagnostics

Отчёт #6 показал регресс: `SCO hold playback` (near-silent WasapiOut на Hands-Free render,
добавленный ранее для удержания HFP-профиля) стартует **до** `new WasapiCapture(...)`, и это,
судя по всему, инвалидирует `MMDevice` для последующего capture — отсюда
`COMException 0x88890008` (`AUDCLNT_E_UNSUPPORTED_FORMAT`) на `IAudioClient.GetMixFormat`.

Это одна корневая причина, проявляющаяся в двух местах:
- Тест гарнитуры падает 3× подряд сразу после SCO hold → EQ=0, кнопка сбрасывается.
- Вероятно тот же механизм используется в главном окне (`Voice toggle: START`) и объясняет
  `peak=0.000` там же — SAPI получает Internal error почти сразу, потому что capture-поток
  на Hands-Free тоже не открылся нормально.

Отдельно, независимо: Play на buds не долетает до приложения, и диагностика конкурирующих
сессий из прошлого пасса сама не работает (`Competing sessions check: manager null`) — то есть
прежде чем делать выводы про P1 (перехват фокуса другим приложением), нужно сначала починить
саму диагностику.

## Файлы пакета

- `01_SCO_Hold_Capture_Order_Fix.md` — патч на порядок операций: не открывать SCO-hold render
  до успешного открытия capture endpoint; плюс защитный retry с пересозданием `MMDevice`.
- `02_SMTC_Manager_Null_Diagnostics.md` — почему `GlobalSystemMediaTransportControlsSessionManager
  .RequestAsync()` может возвращать null и как это продиагностировать/починить, прежде чем
  переходить к самой гипотезе P1.
- `cursor_prompt.txt` — промпт для агента: применить независимо, собрать, вручную проверить
  по инструкции, самоотчёт при нестыковках.

## Порядок применения

1. Сначала `01` — без сигнала на входе (P0 причина 1) чинить/диагностировать что-либо ещё
   бессмысленно, поэтому она первая.
2. `02` — независимо, может выполняться параллельно или после.

## Что НЕ трогать

- Culture/confidence фикс из пасса #4 — уже применён, не трогать.
- `OfflineSttRecognizer` — не менять архитектуру, только если понадобится проверить, что она
  получает реальный сигнал после фикса #1.
- Логика самого AVRCP/hotkey перехвата — в этом пассе только диагностика null manager, не
  попытки агрессивно отобрать фокус у других приложений.
