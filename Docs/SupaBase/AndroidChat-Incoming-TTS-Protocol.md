# AndroidChat — протокол озвучки входящих сообщений

**Дата:** 2026-08-09 (обновлено: теги `[Voice]`)  
**Клиент-эталон:** AndroidChat ≥ 1.0.41  
**Назначение:** единый wire-формат `content` для TTS, чтобы внешние клиенты (Hermes, WpfChat, другие боты) управляли озвучкой предсказуемо.

Связанный контракт таблицы: [Supabase-Messages-Contract-For-External-Clients-2026-07-12.md](Supabase-Messages-Contract-For-External-Clients-2026-07-12.md).

---

## 1. Когда AndroidChat озвучивает

| Условие | Нужно |
|---------|--------|
| `enableIncomingTts` = true | да |
| Сообщение адресовано инбоксу устройства (`recipient_name` = `incomingRecipientName`, обычно `Android`) | да |
| `sender_name` ≠ собственный `senderName` устройства | да |
| Не открыт экран тестов/урока | да |
| В `content` есть ≥1 блок `[Voice]…[/Voice]` с TTS-объектами (см. §2) | да |

Если блоков Voice / TTS-объектов нет — **озвучки нет** (пустой план). Сообщение при этом может отображаться в чате как обычный текст / файл / meta.

---

## 2. Оболочка Voice + формат сегментов

### 2.0. Обязательные теги `[Voice]`

Озвучивается **только** текст **между** тегами:

```text
[Voice]
… здесь форматирование для озвучки …
[/Voice]
```

| Правило | Значение |
|---------|----------|
| Теги | `[Voice]` … `[/Voice]` (регистр не важен) |
| Несколько блоков | допустимы; озвучка по порядку в `content` |
| Вне тегов | **никогда** не озвучивается (даже при наличии `{"en":…}`) |
| Незакрытый / нет пары | блок игнорируется |
| Внутри тегов | прежний формат §2.1 (`{"en":…}` / `{"ru":…}`) |

Пример (озвучится только «Hello»):

```text
лог и diff сюда
[Voice]
{"en":"Hello"}
[/Voice]
{"en":"НЕ озвучивать — вне Voice"}
file:///path/to/shot.png
```

### 2.1. Формат внутри `[Voice]`

Озвучиваются **только** JSON-объекты в фигурных скобках `{…}` с ключами **`"en"`** и/или **`"ru"`** (значения — строки).

Один сегмент:

```text
[Voice]
{"en":"Hello"}
[/Voice]
```

Два сегмента, порядок ключей = порядок озвучки:

```text
[Voice]
{"ru":"Привет","en":"Hi"}
[/Voice]
```

Три сегмента (ключи могут повторяться):

```text
[Voice]
{"en":"Hi","ru":"Как дела?","en":"Good"}
[/Voice]
```

Несколько объектов подряд:

```text
[Voice]
{"en":"First."}
{"ru":"Второй."}
{"en":"Third."}
[/Voice]
```

### 2.2. Смешанный текст

- Текст **вне** `[Voice]…[/Voice]` — не озвучивается.
- Внутри Voice: текст **вне** `{…}` — не озвучивается; объекты `en`/`ru` — озвучиваются.

```text
note for humans
[Voice]
prefix {"en":"Speak only this"} suffix
[/Voice]
```

План: EN → `Speak only this`.

### 2.3. Правила разбора

1. Найти все пары `[Voice]` … `[/Voice]` (case-insensitive), взять тела по порядку.
2. В каждом теле найти сбалансированные объекты `{…}` (с учётом строк и `\"`).
3. Объект — TTS, если:
   - есть хотя бы один ключ `"en"` или `"ru"` со строковым значением;
   - **нет** ключей `"type"` и `"skill"`.
4. Внутри объекта взять пары `(lang, text)` **в порядке появления** ключей (дубликаты допустимы).
5. Пустые строки после trim отбрасываются.
6. Между сегментами — пауза `ttsPauseSeconds` (по умолчанию 3 с).
7. Всё вне Voice и вне TTS-объектов игнорируется для TTS.

### 2.4. Не озвучивается (намеренно)

| `content` | Почему |
|-----------|--------|
| `{"en":"Hello"}` без `[Voice]` | нет оболочки Voice |
| `Привет` / `Hello` | нет Voice и нет `{…}` |
| `[Voice]Привет[/Voice]` | нет объектов `en`/`ru` |
| `{"type":"file",…}` | служебный JSON / нет Voice |
| `[LOG:…] …` | не чат / не TTS |

Минимальный валидный пример:

```text
[Voice]
{"ru":"Привет"}
[/Voice]
```

или

```text
[Voice]
{"en":"Hello"}
[/Voice]
```

## 3. Оболочка сообщения (Supabase)

INSERT в `public.messages`:

| Поле | Пример для озвучки на телефоне |
|------|--------------------------------|
| `sender_name` | `Hermes.Utilities`, `WpfChat`, … |
| `recipient_name` | `Android` (или согласованный inbox) |
| `content` | см. §2 (`[Voice]` + TTS JSON) |
| `sender_id` | `auth.uid()` сессии |

Тип сообщения **не** выносится в отдельную колонку — только формат `content`.

---

## 4. Поведение озвучки (план)

Для

```text
[Voice]
{"en":"Hi","ru":"Как дела?","en":"Good"}
[/Voice]
```

план:

1. Speak `en`: `Hi`
2. Pause
3. Speak `ru`: `Как дела?`
4. Pause
5. Speak `en`: `Good`

Язык сегмента задаёт голос/локаль TTS (`en` / `ru`). Других кодов языка нет.

---

## 5. Рекомендации внешнему клиенту

1. **Хотите озвучку** — оберните фразы в `[Voice]…[/Voice]`, внутри только `{"en":…}` / `{"ru":…}`.
2. **Не хотите озвучку** — не ставьте `[Voice]` (plain / diff / JSON без оболочки молчат).
3. **Служебный текст + речь** — лог/diff/пути снаружи Voice; речь только внутри.
4. **Повтор фразы** — `{"en":"A","ru":"Б","en":"A","en":"A"}` внутри Voice.
5. Экранирование в строках: стандартный JSON (`\"`, `\\`, `\n`, …).
6. С 1.0.41 одних `{"en":…}` **недостаточно** — без `[Voice]` озвучки нет.

## 6. Совместимость и версия

| Версия AndroidChat | Поведение |
|--------------------|-----------|
| &lt; 1.0.40 | Plain text мог озвучиваться целиком |
| 1.0.40 | Только `{"en":…}` / `{"ru":…}`; без требования Voice |
| ≥ 1.0.41 | Обязательны `[Voice]…[/Voice]`, внутри — формат §2.1 |

Код: `MessageDisplayFormatter.toSpeakPlan` / `toVoiceSegments`.

---

## 7. Минимальный чеклист для интеграции

- [ ] Сообщения для телефона: `recipient_name=Android` (или согласованное имя).
- [ ] Озвучка только внутри `[Voice]…[/Voice]`.
- [ ] Внутри Voice — объекты `{"en":…}` / `{"ru":…}`.
- [ ] Проверено: `{"en":"X"}` **без** Voice → молчит.
- [ ] Проверено: diff / `file://` вне Voice → молчит.
- [ ] Проверено: порядок ключей в одном объекте соблюдается.
