# Задачи на 2026-06-11

## 1. Панель моделей основного агента Hermes

**Цель:** отдельная панель в Hermes.Wpf для выбора модели **основного агента** (`hermes chat` в WSL) и мониторинга использования моделей по задачам.

**Требования:**
- Выбор модели / провайдера для main agent (передача `hermes chat -m …` / `--provider …` или синхронизация с `~/.hermes/config.yaml`).
- Мониторинг: какая модель отвечала, на какой задаче/проекте, длительность, exit code, токены (если CLI отдаёт).
- **Отдельный файл логов** использования моделей main agent (не смешивать с общим `hermes_session_*.log` и не с транскриптом чата).
- **Не трогать** модель мини-чата ✦ (OpenRouter / `InAppAssistantOpenRouterModel`, сейчас gemini) — она остаётся как есть.

**Контекст (на момент постановки):**
- WPF сейчас вызывает `hermes chat` без `-m`; модель берётся из `~/.hermes/config.yaml` (`model.default`).
- CLI поддерживает: `-m MODEL`, `--provider PROVIDER` (`hermes chat --help`).

**Связанные файлы (ориентир):**
- `Hermes.Wpf/Services/HermesService.cs` — вызов CLI
- `Hermes.Wpf/Models/HermesSettings.cs` — новые поля настроек
- `Hermes.Wpf/ViewModels/MainViewModel.cs` — turn / session

## 2. Кандидат DeepSeek для desktop-задач (исследование → тест)

**Сценарии Hermes:** скриншоты, мышь, приложения, браузер, bash/tools.

**Рекомендация для первого теста (OpenRouter, тот же провайдер что в config):**

| Модель | ID | Когда |
|--------|-----|--------|
| **DeepSeek V3.2** | `deepseek/deepseek-v3.2` | **Основной выбор** — tool calling, agentic loops, bash/файлы, дешевле R1 |
| **DeepSeek R1** | `deepseek/deepseek-r1` | Сложные многошаговые сценарии (планирование UI), медленнее |
| Gemini flash (текущая) | `google/gemini-3-flash-preview` | Оставить для ✦ чата, не для main agent |

**Почему V3.2:** заточена под agentic tool-use; в Hermes скриншоты идут отдельным vision-пайплайном (`vision_analyze` / метаданные захвата), main model в основном оркестрирует tools и `wpf_local` — V3.2 text + tools подходит лучше, чем чистый coder или distill.

**Проверить в WSL перед внедрением панели:**
```bash
hermes chat -m deepseek/deepseek-v3.2
# smoke: скриншот, простой bash, wpf_local click
```

**Не брать как единственную для GUI:** distill-модели (R1-Distill-*) — слабее на длинных tool-цепочках.

### 5.2 Несколько чатов из разных проектов (Project Manager)

**Цель:** одновременно открывать чаты нескольких проектов из Project Manager (вкладки / панели), а не один выбранный проект на всё окно.

**Ориентиры:**
- Независимые история, CLI-session и busy-state на чат/проект.
- Переключение вкладок без потери несохранённого ввода.
- Rename / settings / Supabase inbound — явно определить, к какому чату относится событие.

### 5.3 Дата и время у сообщений в чате

**Цель:** у каждого запроса пользователя и ответа Hermes в UI чата показывать дату и время.

**Ориентиры:**
- Поле timestamp в модели сообщения; сохранение в history JSON.
- Формат отображения (локальное время): дата + время; для «сегодня» — можно только время.
- Единообразно для локальных turns, восстановления истории и inbound (Supabase / WhatsApp).
