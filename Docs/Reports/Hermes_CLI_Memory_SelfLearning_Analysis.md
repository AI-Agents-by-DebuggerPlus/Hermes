# Анализ: память, самообучение и скилы Hermes CLI в проекте

**Дата:** 2026-07-03
**Контекст:** кейс `water-submit` (проект Utilities, передача показаний водоканала Рені)
**Вопрос:** как в текущей реализации используется память / самообучение / создание скилов Hermes CLI (как задумано Nous Research); сохраняет ли агент данные для будущих подобных задач; помнит ли контекст проекта Utilities.

---

## TL;DR

- **Механизмы Nous Research присутствуют и включены** (`memory_enabled`, `user_profile_enabled`, skills, sessions/resume, AGENTS.md-инъекция, cron). Инфраструктура есть.
- **Но петля самообучения не замыкается автоматически.** В кейсе `water-submit` агент **успешно выполнил** задачу через `browser`, но **не записал** опыт в `~/.hermes/memories/MEMORY.md` и **не создал** собственный скил.
- **Память для будущих задач сохраняется лишь частично:** профиль пользователя (`USER.md`) — да; процедурное знание конкретной задачи — нет.
- **Контекст проекта Utilities агент «помнит» через файлы на диске** (`AGENTS.md`, `hermes/project.md`, `hermes/instruction.txt`) и **resume-сессию**, а **не** через собственную кристаллизованную память агента.

## 1. Что задумано Nous Research (механизмы CLI)

| Механизм | Файл / команда | Назначение |
|---|---|---|
| Долговременная память | `~/.hermes/memories/MEMORY.md` | Обобщённые факты/приёмы между сессиями и проектами |
| Профиль пользователя | `~/.hermes/memories/USER.md` | Устойчивые предпочтения пользователя |
| Идентичность | `~/.hermes/SOUL.md` | Системная персона агента |
| Навыки | `~/.hermes/skills/**/SKILL.md` + `hermes skills` | Переиспользуемые процедуры (создание/установка/использование) |
| Сессии | `~/.hermes/sessions/*.json` + `--resume` | Контекст диалога (эфемерная, разговорная память) |
| Контекст проекта | `AGENTS.md` / `project.md` в cwd | Инъекция правил и данных проекта в промпт |
| Расписание | `hermes cron` (+ gateway) | Автономный запуск задач |
| Чекпоинты | `~/.hermes/checkpoints/` | Снимки состояния |

**Конфиг (`~/.hermes/config.yaml`):**

```yaml
memory:
  memory_enabled: true
  user_profile_enabled: true
  memory_char_limit: 2200
  user_char_limit: 1375
  provider: ''        # локальный файловый провайдер (MEMORY.md/USER.md)
model:
  default: google/gemini-3-flash-preview
  provider: openrouter
toolsets: [hermes-cli]
```

Т.е. память **включена**, провайдер — локальные markdown-файлы.

## 2. Как это подключено в проекте (WPF ↔ CLI)

- **Pure CLI pass-through** (`MainViewModel.ExecutePureCliAgentTurnAsync`): сообщение пользователя уходит в `hermes chat -q '…' -Q --source wpf` **как есть**, без WPF-инъекций промпта, без пост-парсинга, без WPF-памяти. Это соответствует `hermes-core-philosophy.mdc`: «память и skills — только Hermes CLI».
- **Per-project resume** (`HermesCliSessionStore`): для каждого проекта хранится id последней сессии; следующий ход идёт с `--resume <session>`. Даёт **разговорную** непрерывность внутри проекта.
- **Данные проекта на диске** (`ProjectAgentsBootstrapService`): при обращении к проекту создаются `AGENTS.md` и `hermes/` (project.md, credentials.md, screenshots). Hermes CLI подхватывает `AGENTS.md` из cwd.
- **Философия разделения**: `AGENTS.md` проекта Utilities прямо предписывает — писать поставленные задачи в `MEMORY.md`, создавать скилы через `hermes skills` после получения данных, использовать `browser` как fallback, project-specific факты — в `project.md`, а не в `MEMORY.md`.

Вывод: **архитектурно всё настроено «правильно»** — ответственность за память/скилы отдана CLI-агенту.

## 4. Ответы на поставленные вопросы

### 4.1 Сохраняет ли агент в память данные для будущих подобных задач?

**Частично, и не для этой задачи.**

- **Да** — работает профиль пользователя: `USER.md` содержит имя и предпочтения (заполнено ранее автоматически). Значит механизм извлечения памяти в CLI в принципе функционирует.
- **Нет** — процедурное/проектное знание по `water-submit` **не сохранено**: ни в `MEMORY.md`, ни как скил. При следующем запуске (в т.ч. cron 01.08) агент будет заново выводить всё из `instruction.txt`/`project.md`, а не из выученного навыка.

### 4.2 Помнит ли агент контекст проекта Utilities?

**Да, но не «своей» памятью.** Источники контекста:

- **Файлы на диске** — `AGENTS.md`, `hermes/project.md`, `hermes/credentials.md`, `hermes/instruction.txt` (инъектируются/читаются из cwd проекта).
- **Resume-сессия** проекта — разговорная непрерывность внутри Utilities.

**Чего нет:** агент **не** переносит проектный опыт в собственную долговременную память/скилы. Убери файлы проекта — и «память» о задаче исчезнет. Это противоречит духу самообучения: контекст держится на внешних файлах, а не на выученном агентом.

## 5. Разрывы относительно замысла Nous Research

1. **Нет авто-кристаллизации после успеха.** Модель `gemini-3-flash` + промпт приоритизируют действие; шаг рефлексии/сохранения пропускается (сам агент это подтвердил: «мои системные настройки приоритизируют действие»).
2. **`MEMORY.md` не обновляется агентом**, хотя `AGENTS.md` это предписывает и `memory_enabled: true`.
3. **Скилы агент не создаёт сам.** (Предзасеянный вручную скил `reni-water-submit` — костыль, к тому же не использовался.)
4. **`MEMORY.md` замусорен WPF-инъекциями** (flashcard/tutor блоки, `[System / Hermes WPF]`) из старой не-CLI логики — противоречит философии «MEMORY.md — только обобщённый опыт агента».
5. **Проектный контекст держится на внешних файлах**, а не на выученной памяти агента.

## 6. Рекомендации (для будущей реализации)

Замкнуть петлю самообучения так, чтобы после успешного выполнения агент **сам**:

1. **Обновлял `MEMORY.md`** — статус задачи (`in-progress → done`) + краткий обобщённый приём (без секретов).
2. **Кристаллизовал скил** из успешного прогона (`hermes skills` / skill_save), а не получал его извне.
3. **Разделял** project-specific факты (→ `project.md`) и переносимые приёмы (→ `MEMORY.md`/skill) — как уже описано в `AGENTS.md`.
4. Был **триггер рефлексии** в конце задачи (reflection/crystallize step) — либо через промпт-хук, либо через настройку авто-извлечения памяти CLI.
5. **Почистить `MEMORY.md`** от WPF-инъекций (legacy), чтобы память соответствовала CLI-first философии.
