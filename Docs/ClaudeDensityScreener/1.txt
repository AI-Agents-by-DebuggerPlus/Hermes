# План реализации

**Шаг 1 — Модели данных** (`models.py`) — `DensityLevel`, `OrderBookSnapshot`, конфиг.

**Шаг 2 — Live-ордербук** (`orderbook.py`) — восстановление локального стакана по схеме Binance (REST snapshot + WS diff, проверка lastUpdateId/sequence, пересинхронизация при разрыве).

**Шаг 3 — Binance-клиент** (`binance_client.py`) — REST снапшот `/api/v3/depth`, WS `@depth@100ms` и `@aggTrade`.

**Шаг 4 — Детектор плотностей** (`density.py`) — бакетизация объёма, порог по перцентилю/std, требование "прожить" N секунд (антиспуфинг), volume profile (footprint) из сделок.

**Шаг 5 — Storage / IPC-слой** (`storage.py`) — запись JSON-снапшота (совместимо с file-based IPC Hermes) + заготовка под Supabase.

**Шаг 6 — CLI-оркестратор** (`cli.py`) — цикл сбора → детекция → запись, конфигурируемый интервал.

**Шаг 7 — Тесты на синтетике** — у меня в песочнице нет доступа к binance.com (сеть ограничена), поэтому логику ордербука и детектора проверю на сгенерированных данных, а сетевой клиент оставлю готовым к реальному подключению у вас.

Ключевое:
- **`orderbook.py`** — live-стакан по официальной схеме Binance (snapshot + diff, проверка sequence, детект разрыва).
- **`binance_client.py`** — REST/WS-клиент с автопересинхронизацией. Реального доступа к `binance.com` из этой песочницы нет (сеть ограничена белым списком), поэтому эта часть не прогонялась вживую — проверьте у себя перед продакшеном.
- **`density.py`** — детекция стенок в стакане с анти-спуфинг фильтром (плотность должна "прожить" N секунд) + volume profile по исполненным сделкам + слияние (стенка + подтверждение профилем = `source: both`, самый надёжный сигнал).
- **`storage.py`** — атомарная запись JSON-снапшота, формат уже содержит всё нужное агенту: `price`, `side`, `strength`, `source`, `distance_pct`, `eaten_ratio`.
