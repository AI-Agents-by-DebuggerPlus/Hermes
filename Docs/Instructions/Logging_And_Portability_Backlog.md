# Бэклог: логи и переносимость (после основного функционала)

Пункты ниже реализованы для улучшения переносимости и удобства отладки.

## 1. Каталог логов без жёсткого диска `D:\` (ВЫПОЛНЕНО)

- Логи перенесены в `%AppData%\HermesWpf\logs\`.
- Путь определяется динамически через `Environment.SpecialFolder.ApplicationData`.

## 2. Ротация и сортировка файлов логов (ВЫПОЛНЕНО)

- Число хранимых сессий увеличено до 10.
- Сортировка при удалении старых логов теперь идет по `LastWriteTimeUtc`, что предотвращает ошибки при копировании файлов.

## 3. Уровни и дублирование (ЧАСТИЧНО ВЫПОЛНЕНО)

- Добавлен метод `LogWarn` в `LogService`.
- Явные уровни INFO / WARN / ERROR используются при записи.

## 4. Документация для пользователя (В ОЧЕРЕДИ)

Кратко описать в справке/Help: где лежат логи на типичной установке.

---

При реализации не забыть: миграция для пользователей, у которых уже накопились логи по старому пути (одноразовое копирование или symlink не требуется, но можно упомянуть в release notes).

## Транскрипт чата (уже реализовано)

Сообщения **User / Hermes** (как в UI, без системного блока напоминания) дополнительно пишутся в UTF‑8 BOM:

`%LocalAppData%\HermesWpf\chat_logs\chat_{YYYYMMDD_HHmmss}.log`

Время `{YYYYMMDD_HHmmss}` совпадает с суффиксом файла основной сессии `hermes_session_*.log` в этом запуске. Путь к файлу транскрипции также выводится в основной лог строкой **`[startup] Chat transcript file: …`**.

Если в настройках задан общий корень доступа Hermes (**Hermes workspace root**), при старте в лог пишется **`[startup] Hermes workspace root (when set): …`**, при первой команде **`[workspace] Hermes процессы используют общий корень: …`**.

## Smoke Hermes CLI (уже в репозитории)

Для быстрой проверки окружения WSL + venv + `hermes` используется скрипт:

`scripts/smoke_hermes_cli.ps1`

Пример: `pwsh -File scripts/smoke_hermes_cli.ps1` (параметр `-Distro` при необходимости). Код выхода совпадает с результатом `wsl.exe`. В CI можно вызывать только на агентах, где разрешён WSL.
