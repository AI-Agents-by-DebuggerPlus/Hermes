# Hermes — краткий план на будущее

Детали уточняются по ходу разработки.

## Контекст агента и выполнение задач

- Продолжать улучшать понимание контекста и точность действий Hermes (формулировки задачи, outbound-инструкции, диагностика по логам).
- Иногда сохранять неточности как норму для сложных задач; усиливать приёмочные критерии и проверку результатов там, где важнее всего.

## Канал связи

- **Supabase** — основной транспорт (уже проверено).

## Удалённый голосовой клиент (Android)

- На устройстве: распознавание речи (голос → текст).
- Передача в **Supabase**; на ПК — **WPF** забирает сообщения и встраивает в существующий поток общения с агентом.
- По мере работы зафиксировать: порядок сообщений, дубликаты, сессии и безопасность доступа.

## «Трансляция» состояния экрана со стола

- Не потоковое видео, а **скриншоты** с заданным интервалом или **по запросу**.
- Отправка через **Supabase** (табличные записи + **Storage** для файлов разумнее, чем тянуть огромный бинарь в каждое событие).
- Клиент просмотра: **WPF** и/или **веб (в т.ч. страница на WordPress)** — выбор некритичен сначала; одна модель данных в Supabase позволит добавить второй клиент позже.

## Открытые решения позже

- Кто инициирует снимок экрана: только расписание, только команда с телефона, или оба варианта.
- Лимиты частоты/разрешения скриншотов под квоты и приватность.
