В **Hermes Agent** концепции **Persistent Memory** (Долговременная память) и **Skill Generation** (Генерация навыков) работают в синергии. Если в обычных ИИ-агентах память — это просто лог контекста, а навыки — это жестко прописанный код, то в Hermes это замкнутая экосистема самообучения.

Когда эти функции активны, агент превращается из одноразового исполнителя скриптов в постоянно развивающуюся систему, которая помнит свои ошибки и буквально дописывает сама себя.

## ---

**1\. Глубокое погружение в концепции**

### **Persistent Memory (Долговременная постоянная память)**

Она разделена на три уровня, что позволяет агенту не «забывать» контекст при перезапуске сессий и не перегружать контекстное окно LLM:

1. **Short-Term (Эпизодическая):** Текущий лог команд и ответов внутри одной сессии (хранится в оперативной памяти/Redis).  
2. **Long-Term Семантическая (Векторная база):** Сюда сохраняются ключевые выводы, факты о пользователе, конфигурации проектов и успешные цепочки рассуждений. База индексируется эмбеддингами. Когда вы ставите новую задачу, Hermes делает поиск по векторной базе и достает релевантный прошлый опыт.  
3. **Логическая (SOUL.md):** Глобальный файл состояния агента, его «личность» и правила поведения, которые он сам может корректировать по итогам работы (если ему разрешено).

### **Skill Generation (Автоматическое создание навыков)**

Это реализация концепции *Voyager* или *Voyager-like* агентов. Когда вы даете Hermes сложную или нестандартную задачу (например, «напиши парсер для сайта X и отфильтруй данные по критерию Y»), он действует по следующему алгоритму:

1. **Пробы и ошибки:** Пытается решить задачу в изолированной среде (Sandbox), анализируя ошибки компиляции или выполнения.  
2. **Рефлексия (Reflective Phase):** Когда задача успешно решена, субагент-аналитик изолирует чистый, переиспользуемый код (на Python/Bash).  
3. **Документирование:** Оформляет этот код в виде структурированного навыка по стандарту agentskills.io.  
4. **Сохранение:** Записывает новый файл .js или .py в локальную директорию навыков (\~/.hermes/skills/). В следующих сессиях этот навык становится доступен агенту как базовая системная команда (Tool/Function).

## ---

**2\. Как активировать и настроить**

Вся конфигурация Hermes Agent управляется через глобальный файл настроек. Обычно он находится по пути \~/.hermes/config.toml (или .yaml, в зависимости от версии сборки).

### **Шаг 1: Редактирование конфигурационного файла**

Откройте конфигурационный файл в редакторе и приведите блоки памяти и генерации навыков к следующему виду:

Ini, TOML

\[memory\]  
\# Включение постоянной памяти  
persistent\_memory \= true  
\# Выбор движка для векторной памяти (хромиум/chroma или qdrant)  
vector\_db \= "chroma"   
\# Путь к локальному хранилищу БД  
storage\_path \= "\~/.hermes/memory\_db"  
\# Глубина извлечения контекста (сколько похожих эпизодов доставать из памяти)  
top\_k\_episodes \= 5

\[skills\]  
\# Разрешить агенту самостоятельно создавать новые навыки  
skill\_generation \= true  
\# Путь, куда будут сохраняться сгенерированные инструменты  
skills\_dir \= "\~/.hermes/skills"  
\# Максимальное количество попыток (итераций) на генерацию и тесты одного навыка  
max\_generation\_attempts \= 3  
\# Обязательное автоматическое тестирование созданного навыка перед сохранением  
run\_tests\_before\_save \= true

\[sandbox\]  
\# Важно\! Для безопасной генерации навыков код должен выполняться в изоляции  
mode \= "docker" 

### **Шаг 2: Применение настроек через CLI**

Если вы предпочитаете настраивать систему интерактивно, можно использовать встроенный мастер:

Bash

hermes config set memory.persistent\_memory true  
hermes config set skills.skill\_generation true

После изменения конфигурации обязательно перезапустите демона или сессию агента:

Bash

hermes restart

## ---

**3\. Как проверить, что это работает?**

### **Проверка памяти:**

Дайте агенту вводную информацию, например:

*«Рабочий проект X использует С\# и Named Pipes для обмена данными».*

Закройте сессию (exit), откройте заново через некоторое время и спросите:

*«Что ты помнишь о технологическом стеке проекта X?»*

В логах терминала (или WebUI в разделе Vector DB Logs) вы увидите, как перед ответом сработал триггер Querying vector memory... и агент извлек нужный эмбеддинг.

### **Проверка генерации навыков:**

Дайте ему комплексную задачу, под которую у него нет готового инструмента из коробки, например:

*«Напиши скрипт, который сканирует локальную папку downloads, находит там все поврежденные zip-архивы, логирует их имена в текстовый файл сломанных архивов, а целые перемещает в архивную папку».*

В процессе выполнения вы заметите в консоли фазы:

1. Executing task in sandbox...  
2. Task succeeded. Initiating skill crystallization... (Кристаллизация навыка)  
3. Skill 'manage\_zip\_downloads' successfully generated and saved.

После этого вы можете заглянуть в папку \~/.hermes/skills/ — там появится новый файл навыка со спецификацией, кодом и метаданными, который Hermes теперь будет использовать автоматически при похожих запросах.

Хотите настроить конкретную модель под эту задачу (например, локальную через Ollama), чтобы функция Function Calling для генерации навыков работала максимально точно и без сбоев?
