```markdown
# Hermes.Wpf — Core Philosophy & Development Rules
**Версия: 1.0** | **Дата: 31 мая 2026**

## Главная цель проекта
Hermes.Wpf — это **удобный графический интерфейс** (UI + Desktop Integration) для основного агента **Hermes CLI** от Nous Research.

**Ключевое правило всего проекта:**

> **Максимально возможное использование возможностей оригинального Hermes CLI**  
> (накопление опыта, persistent memory, closed learning loop, самообучение и автоматическое создание/улучшение навыков).

Hermes.Wpf **не должен** заменять или дублировать логику агента. Он должен быть **тонким, умным слоем**, который передаёт как можно больше контекста, опыта и контроля в Hermes CLI.

### Обязательные принципы (соблюдать всегда)

1. **Learning Loop на уровне Hermes CLI — приоритет №1**
   - Любое значимое действие пользователя или агента (выполнение задачи, получение новой информации, автоматизация, обработка данных) должно по возможности проходить через Hermes CLI.
   - Локальные handlers (Reni Water, Desktop Capture, Trading и т.д.) **обязаны** участвовать в цикле обучения:
     - После выполнения вызывать `MemoryExtractorService`
     - Вызывать `RoleExperienceCapture`
     - Формировать опыт для External Brain (Obsidian vault)
     - Инициировать создание/обновление Generated Skill при повторяющихся успешных действиях.

2. **"Thin UI + Thick CLI" Architecture**
   - WPF-приложение в первую очередь — интерфейс общения, мониторинга, настройки и запуска.
   - Вся долгосрочная память, reflection, skill generation и самообучение должны происходить **внутри Hermes CLI**.
   - Локальные C# handlers используются только для:
     - Действий, требующих прямого доступа к Windows (Playwright, mouse/keyboard, desktop vision, notifications и т.д.).
     - Быстрых операций, где запуск CLI был бы избыточен.
   - После каждого локального действия **обязателен Post-Execution Hook**, который передаёт результат и контекст в Hermes CLI.

3. **Автоматическое создание и улучшение навыков**
   - Агент должен стремиться "кристаллизовать" повторяющиеся задачи в полноценные Generated Skills (как в оригинальном Hermes).
   - После 2–3 успешных выполнений одной и той же задачи — предлагать или автоматически создавать skill.
   - Все Generated Skills должны быть доступны как через UI, так и через CLI.

4. **Память и External Brain**
   - External Brain (Obsidian vault) — главный источник долгосрочной памяти.
   - Любая новая информация, успешное/неуспешное действие, настройки пользователя должны попадать в vault.
   - Синхронизация WSL ↔ External Brain должна быть двусторонней или хотя бы надёжной в одну сторону.

### Правила при реализации новых фич и рефакторинге

- Перед написанием кода спрашивай себя:  
  **"Как сделать так, чтобы это максимально использовало возможности Hermes CLI?"**

- При создании новых локальных handlers **обязательно**:
  - Добавить PostLocalExecutionHook
  - Передать структурированный результат в CLI
  - Обеспечить попадание в Memory / Experience Capture

- При работе с промптами — всегда добавляй в system prompt описание текущих built-in возможностей WPF (чтобы агент знал, что может делать локально).

- Безопасность: пароли, токены и чувствительные данные хранить через Windows Credential Manager или Secret Vault, а не в plaintext.

- Код должен быть модульным, хорошо задокументированным и следовать существующему стилю проекта.

### Запрещено
- Создавать дублирующую логику памяти и навыков только внутри WPF.
- Отключать learning loop для "удобства".
- Делать важные автоматизации только через Assistant Mode (прямой OpenRouter) без участия CLI.

---

**Эти правила имеют высший приоритет.**  
При любом конфликте между удобством UI и сохранением learning loop оригинального Hermes — **выигрывает learning loop**.

Каждый новый PR или значимое изменение должно соответствовать этим принципам.
```
