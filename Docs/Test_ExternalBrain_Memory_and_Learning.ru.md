# Как протестировать память и «самообучение» (Hermes.Wpf)

Краткая памятка по проверке External Brain и сохранения опыта через клиент Hermes.Wpf.

## 1. Путь к памяти

В **Settings → External Brain** укажите папку с `*.md` (обычно `...\HermesBrain\Memory` или корень vault).  
В логе при загрузке смотрите строку вида `[external-brain] loaded N *.md`.

## 2. Загрузка и разбор заметок

Откройте **External Brain**: список заполняется из кеша ; колонки **Тип** и **важность** берутся из YAML frontmatter (`type`, `importance` и т.д.).

## 3. Контекст в промпте

Включите подмешивание в промпт (**inject into prompt**) и лимит фрагментов (по умолчанию до **20**, в настройках **1–20**).  
Задайте вопрос по тексту, который есть только в сохранённых заметках (или по тегу из YAML / `#tag` в теле).  
В логе должна быть строка **`[external-brain] outbound context chars=...`** — блок памяти отправлен в Hermes CLI.

## 4. Сохранение опыта (ручное обучение)

После успешного ответа Hermes используйте **«Save experience»** (главное окно или чат). Выберите тип, теги, важность, при необходимости отредактируйте Markdown и сохраните в vault — watcher перечитает файлы автоматически.

## 5. Сквозной тест

1. Создайте заметку с уникальной фразой и тегом `#hermes_test_memory`.  
2. Убедитесь, что она видна во **External Brain** (или дождитесь перезагрузки).  
3. В чате спросите по этой фразе или тегу.  
4. Проверьте лог контекста и ответ модели по сути заметки.

## 6. Если не работает

- Путь к пустой или неверной папке — блок не строится.  
- **`USER ACTION REQUIRED: No memory files found`** — в каталоге нет успешно разобранных `*.md`.  
- После **Save experience** файл должен появиться на диске и в списке External Brain после reload.
