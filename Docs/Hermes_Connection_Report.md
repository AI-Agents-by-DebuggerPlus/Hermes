# Отчет по подключению `Hermes.Wpf` к Hermes

## Что уже реализовано

### 1) Мост WPF → WSL → Hermes
- В `Hermes.Wpf/Services/HermesService.cs` реализован запуск `wsl.exe` через `ProcessStartInfo`.
- Используется активация окружения: `source ~/hermes-agent/venv/bin/activate`.
- Реализованы команды:
  - чат: `hermes chat -z '<message>'`
  - быстрые действия: `hermes <command>` (status, gateway run, reset-webhook).
- Поддержан запуск с рабочей директорией проекта через `--cd "<wsl-path>"`.

### 2) Передача контекста проекта
- В `Hermes.Wpf/Services/ProjectService.cs` реализована конвертация пути Windows в WSL-формат:
  - `D:\Work\Project` → `/mnt/d/Work/Project`.
- В `MainViewModel` выбранный проект используется как контекст для всех запросов к Hermes.

### 3) Поток вывода и отображение в UI
- `stdout/stderr` из процесса Hermes читаются асинхронно.
- Каждая строка транслируется через `OutputReceived` и выводится в `Terminal Output`.
- Ошибки также отражаются в терминале (`[error] ...`).

### 4) Работа с чатом
- Сообщения пользователя и ответы Hermes сохраняются в чат-модели.
- История по проектам сохраняется и загружается из JSON (`HistoryService`).
- Отправка сообщения:
  - `Enter` — отправка,
  - `Shift + Enter` — перенос строки.

### 5) Логирование процесса интеграции
- Реализовано отдельное окно логов + файловое логирование (`LogService`, `LogsWindow`).
- Логи пишутся в `D:\Programming\AI_Agents\Hermes\Docs\Logs`.
- Реализована ротация: хранится не более 3 последних лог-файлов.

## Что нужно сделать для полноценного подключения

### Обязательные внешние условия
1. Установить и проверить WSL на Windows.
2. Внутри WSL установить Hermes CLI (команда `hermes` должна быть доступна).
3. Подготовить окружение `~/hermes-agent/venv` с нужными зависимостями.
4. Проверить базовую команду вручную в WSL:
   - `source ~/hermes-agent/venv/bin/activate && hermes status`

### Что рекомендуется добавить в приложение (следующий шаг)
1. **Preflight-проверка при старте**:
   - проверка доступности `wsl.exe`,
   - проверка `hermes --version`/`hermes status`,
   - валидация пути к `venv`.
2. **Явная конфигурация интеграции в UI**:
   - путь к venv,
   - альтернативная команда Hermes,
   - таймауты для chat/quick actions.
3. **Диагностика ошибок подключения**:
   - отдельные коды/категории ошибок (WSL unavailable, hermes not found, timeout, auth).
4. **Неблокирующие статусы выполнения**:
   - индикатор выполнения команд и понятные статусы в UI.

## Текущий статус

Базовый контур подключения к Hermes уже работает на уровне архитектуры и кода.  
Для гарантированной рабочей эксплуатации осталось подтвердить внешнее окружение (WSL + Hermes + venv) и добавить preflight-диагностику в приложении.
