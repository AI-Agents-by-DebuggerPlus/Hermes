- `Docs/Logs/hermes_session_20260429_134601.log`
- `Docs/Logs/hermes_session_20260429_133540.log`

## Наблюдаемая ошибка

Во всех последних попытках reconnect повторяется одна и та же ошибка:

- `WSL_E_DISTRO_NOT_FOUND`
- `There is no distribution with the supplied name.`

В логах это появляется как:

- `[ERROR] [connection] Venv failed: ... WSL_E_DISTRO_NOT_FOUND`

## Что это означает

Ошибка возникает до фактической проверки venv/Hermes и указывает, что `wsl.exe` не может открыть дистрибутив с именем, которое передает приложение через `-d "<WslDistro>"`.

То есть основная проблема сейчас не в `bash`, не в `venv` и не в `hermes`, а в несоответствии имени дистрибутива в момент выполнения reconnect.

## Вероятные причины

1. В активном экземпляре приложения установлено неверное значение `WslDistro`.
2. Работает старый экземпляр приложения с устаревшими настройками (watchdog продолжает писать ошибки).
3. Дистрибутив был изменен в настройках, но reconnect выполнялся до полного перезапуска приложения/окна.

## Что проверить

1. Полностью закрыть все процессы `Hermes.Wpf`.
2. Запустить приложение заново.
3. В `Settings` убедиться:
   - `WSL Distro = Ubuntu`
   - `Venv Path = ~/hermes-agent/venv`
   - `Hermes Command = hermes`
4. Нажать `Reconnect`.
5. Проверить новый лог: ошибка `WSL_E_DISTRO_NOT_FOUND` должна исчезнуть.

## Подтверждение внешнего окружения

Системные команды вручную выполняются корректно:

- `wsl -d ubuntu -- /bin/bash -lc "echo ok"` → `ok`
- `wsl -d ubuntu -- /bin/bash -lc "source ~/hermes-agent/venv/bin/activate && hermes status"` → успешный статус Hermes

Это подтверждает, что инфраструктура WSL + Hermes рабочая, и проблема локализуется в передаваемом имени дистрибутива/сессии приложения.
